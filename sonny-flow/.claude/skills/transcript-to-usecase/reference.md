# transcript-to-usecase ─ 詳細手順

## 手順
1. CLAUDE.md の Input 配置で「書き起こしファイルの場所」を確認
2. 対象ファイルを読む。**5000行超 / 100KB超なら章/トピックで分割**してから処理
3. 各章で以下を抽出：
   - ユースケース候補（「〜したい」「〜できる必要がある」等の発言）
   - ユーザストーリー（As a / I want / So that）
   - 業務ルール候補（「こういうときはこう処理」「これは必ず」等の発言）
   - 未決定事項（「これは決まっていない」「後で決める」等）
   - 矛盾点（複数発言で食い違う箇所）
4. すべての抽出項目に**元ファイルの行番号参照を必ず付ける**（`source: inputs/transcripts/xxx.vtt:L120-180`）
5. 章ごとの結果を結合して最終アウトプットへ
6. 抽出後、[`uncertainty-report`](../uncertainty-report/SKILL.md) で推測箇所を別ファイルに出す

## 章分割のヒント

書き起こしの分割基準（プロジェクトに合わせて選ぶ）：
- 時間ベース：30分ごと（1時間ヒアリング→2章）
- トピックベース：話題が変わった所で区切る
- 話者ベース：質疑応答が変わった所で区切る

機械的に均等分割でも構わない。**1コンテキストに全部載せようとしない**ことが最優先。

## 出力Markdown構造

```markdown
# {feature} 書き起こし抽出結果

## ユースケース候補
- UC1: ... (source: xxx.vtt:L120-130)

## ユーザストーリー候補
- US1: As a ..., I want ..., so that ... (source: xxx.vtt:L200-215)

## 業務ルール候補
- R1: ... (source: xxx.vtt:L300-310)

## 未決定事項
- TBD1: ... (source: xxx.vtt:L450)

## 矛盾点
- Conflict1: 発言Aとの食い違い (source: A=L100, B=L350)

## 雑談・脱線（参考）
- ...
```

## 守るべき詳細ルール
- **発言の解釈を補完しない**。発言ベースで残し、補完が必要な箇所は `(推測)` を付ける
- 話者名・個人名を含めない（役割名「PM」「業務担当者」等に置換）
- 雑談・脱線は `out_of_scope` に記録だけして、本抽出には含めない
- 章分割は機械的でよい（時間帯で区切る等）。**1コンテキストに全部載せようとしない**
- 抽出後は必ず `requirements-organizer` の人インタビューで補強する（書き起こしだけで要件確定しない）
