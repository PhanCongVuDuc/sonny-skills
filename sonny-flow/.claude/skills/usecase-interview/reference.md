# usecase-interview ─ 詳細手順

## 手順
1. ユーザに業界・システム種別・対象機能を聞く
2. 以下の観点を**順番に・1問ずつ**質問する：
   1. 数値の計算・精度・丸め処理に関するルール
   2. エラー・例外時の業務上の対処（補正・通知・ログ）
   3. データの発生・更新・削除に関する制約
   4. 「このお客さんだけ」「この時期だけ」の特例処理
   5. 「当たり前すぎて仕様書に書かれていない」前提
   6. 法規制・行政ルール・業界標準
   7. 処理順序の依存（A→B の順で動かないとならない等）
3. 各回答に対し、曖昧なら同じ観点で深掘りする（決め打ちで次の観点に進まない）
4. すべて終わったら整理結果を Markdown で出力

## 出力Markdown構造
- ユースケース一覧
- ユーザストーリー一覧（As a / I want / So that）
- 引き出した暗黙の業務ルール（カテゴリ別）
- 未確認事項（インタビュー中に確認できなかった点）

## 守るべき詳細ルール
- 一度に複数質問しない（1問1答）
- ユーザの回答を勝手に解釈・補完しない
- 自分で答えを推測して質問をスキップしない
- 回答が曖昧な場合は深掘り質問を出す（決め打ちで次の観点に進まない）
- インタビュー後の整理段階で初めて推測が入る場合は `（推測）` を必ず付ける
